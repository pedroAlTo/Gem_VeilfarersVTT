# VeilFarers VTT · v1.2.0 · Orbital

A local-first virtual tabletop with scene travel, a player roster, shared drones, character JSON import, optional Firebase accounts, and a Three.js Hope & Fear dice tray.

Current release: **v1.2.0**. Download package: **VeilFarers_VTT_v1.2.0.zip**. Open **AYUDA** in the top menu for the installed version, quick guide and changelog. The application version is independent of Corebook 12.06. [CHANGELOG.md](CHANGELOG.md) records numbered releases; [RELEASE_ORBITAL.md](RELEASE_ORBITAL.md) retains the original technical history.

## Run locally

On Windows, extract the ZIP and run **INICIAR_VTT_RED_LOCAL.bat** on the Keeper’s PC. Other devices on the same Wi-Fi or Ethernet network open the printed address, for example `http://192.168.1.42:5173/`. Create a game in **Session** and share its invitation. Players select **PLAYER → Join game** and paste the invitation. The Keeper sees **Crew · 1** after the first player joins. Assign a token in the roster. Dropping it on either map updates its position for the other participants. The LAN launcher sends game data through the same VTT server on port 5173. It works without public signaling after dependencies are installed.

**INICIAR_VTT_LOCAL.bat** opens the menu for LAN, single-PC offline play, tests and the effects lab. **INICIAR_VTT_ONLINE.bat** uses PeerJS for online play and requires internet for signaling. The launchers require Node.js 22.12+ or 24 LTS and install locked dependencies on first use.

On macOS/Linux, run `npm ci`, then `VITE_SESSION_TRANSPORT=lan VITE_LOCAL_ONLY=0 npm run dev -- --host 0.0.0.0 --port 5173 --strictPort` for LAN play. Run `node scripts/lan-info.mjs` to display client URLs. For local checks use `npm test` and `npm run build`.

## Encounters in v1.2.0

- **SCENES → Definir entorno / activar con Fear**: choose the micro stat block and one Passive or Action macro feature (Keeper 12.06, chapters 9–10). Tier scaling and DC are shown from the book. Save before activating; Fear costs are printed costs, and reactions require the stated trigger. Roll and resolve consequences at the table. Visuals are optional and separate from weather.
- **ROSTER → Biblioteca de adversarios → Colocar como boss**, or an enemy **Ficha → Boss · estados**: configure 2–8 phases or load one of 17 Keeper profiles. Unprinted values visibly inherit the base adversary. Review them before play. Transitions are Keeper-controlled; +2 Fear, or +3 for the final phase, capped at 12. Objective/clock mechanics and special abilities follow their source text, not automatic damage logic.
- **DICE → Damage → Impacto del arma**: weapon-derived or explicit presentation. Only applied damage triggers an impact, sized from actual HP lost. Armor expenditure produces shield feedback; direct bypass does not. `/fx-lab.html` demonstrates ballistics, plasma, fire, cryo, explosions and clipped fire areas.
- In **SCENES**, choose another arc or **Sin arco** for any scene. Wait for **SAVED** before closing or reloading. Arc membership is now part of campaign persistence and export.

## Play

- **Water → Polígono**: click each vertex, then click the first vertex, double-click, press Enter or select **Cerrar polígono**. Backspace removes the last point; Escape, right-click or **Cancelar** discards the draft. Switching tools, shapes, scenes, roles or layers also discards unfinished water. The actual polygon is saved and shared, including coordinates at zero; **Caja** remains drag-to-draw. Water must be visible and unlocked. Existing zones previously saved as default rectangles have no original vertices to recover and must be redrawn.
- **CHAT**: select **Mesa · todos** for public messages or a private Keeper–player conversation. The Keeper can also use **Session → Player roster → Susurrar**. Players can whisper to the Keeper; player-to-player whispers are not included. Enter sends, Shift+Enter inserts a line, and each channel keeps a separate draft. Unread counts identify conversations with new messages. A disconnected recipient disables sending without changing the destination; a failed send retains the draft for retry.
- Chat keeps the last **500 messages across the session**, with up to 2000 characters each. The Keeper's saved session and JSON export contain public messages and whispers. Guests only receive public messages and their own whispers, including reconnect snapshots; these do not overwrite the guest's local campaign. Reconnecting with the same invitation and browser-session identity restores that player's available history while the host remains open. A new browser identity cannot retrieve another player's private thread. There are no read receipts or offline delivery queue. Local Keeper messages are saved to the table and become visible when players join.
- **Token → ESTADOS** or **Ficha → Condiciones**: toggle the 18 standard conditions from Corebook 12.06, Chapter 10, with the original rules available in the panel. Add custom markers for scene-specific effects. Icons appear beside visible tokens and labels appear in the quickbar. Conditions are shared, saved and undoable; their effects and durations are resolved manually. The Hidden condition does not make a token private. The Keeper and assigned players can edit; other players can consult.
- **Token → EQUIPO** or **Ficha → Armas y equipo**: view imported weapons, kits and items; add/edit/remove weapons and quantities in **Editar inventario**. **Preparar daño** fills the dice panel and retains its selected target. Imported final damage is not expanded a second time; base damage adds Proficiency and Honed Edge once. Expressions such as `1d8+1 Phys + 1d4 Shock` are supported. Alternative attacks, keep-highest procedures, resistances and special features need manual resolution. Inventory edits are stored in sessions and native VTT actor exports; **Exportar al creador** retains the original creator equipment. Reimporting a system sheet preserves an existing VTT inventory override.
- **Dice → Tirada secreta · solo Keeper**: hide a check, Bear Down or damage roll from player logs and network messages. The Keeper can roll without selecting a token. Private results remain in the Keeper's saved session; switching to Player hides them. Resource changes on visible characters still synchronize normally. Session exports contain Keeper information and are intended for the Keeper.
- **Roster → Biblioteca de adversarios**: search by name, ability or type, then filter by book and tier. The catalog reads the supplied 12.06 texts: Alien Species (Threats and Adversaries), Keeper’s Companion (Galactic Bestiary, Section A), and Rust & Steel (Broker Profiles). It contains 57 profiles, 42 directly deployable. Each deployed copy has independent resources and appears hidden by default at the center of the current view. Full printed descriptions and abilities remain in **Ficha → Notas y habilidades**. The other 15 profiles stay available for reference because they require special encounter procedures or lack complete numeric thresholds. Unprinted Stress/Armor tracks have zero slots; special abilities and alternative attacks require manual resolution.
- **Session** → Host game: name the current campaign and copy its invitation. Players paste the complete code or link and enter their call sign. An account is optional. The top menu always shows connection state, campaign name and invitation.
- **Session** → Player roster: the Keeper assigns any non-drone token to a player. Reassignment releases that player's previous token. Players can import their own character or use a cloud character; replacement keeps their existing token and assignment.
- **My tokens** opens the character and shared drones you control in the current scene. Select one to center the map, move it, aim its facing handle, make a check or edit its current resources in **Ficha**. The Keeper manages assignments and resource limits.
- **Anomaly color** opens a palette for lightning and laser effects. Drag in the color field, adjust hue, choose a swatch or enter a hex value. The effect previews the selected color immediately.
- **Roster** → + Actor → Drone: create a drone. In its **Ficha → Player controls**, select multiple controllers. Drone controls are also available in Session. Non-drone tokens allow one controller; a player may control one non-drone plus several drones.
- **Scenes**: switching or creating a scene moves player characters, assigned NPCs and controlled drones. Encounter enemies stay behind. Returning restores per-scene positions, clamped to map bounds. Keeper-owned legacy enemies are not party members.
- **Dice → Open tray**: opens a compact overlay at the map’s top right. Minimize it to keep just the results, or close it; the map remains interactive. Open **Dice settings (⚙)** for Crystal caves, Tech panels, Circuits & processors, Galaxy & stars, test throws, automatic display, reduced motion and camera controls. Hope stays cyan and Fear stays magenta, with clear labels. The finishes use detailed color/relief/illumination maps, beveled edges, reflected light and clearcoat. Three.js WebGL 2 renders real d12 meshes; cannon-es runs collisions at 120 Hz. Throws use lower launch/spin speeds and mat friction to settle naturally, without kicks or teleports. Cocked or overlong trajectories are rejected before animation. Game checks preserve the authoritative result; test throws are cosmetic. Drag to orbit or scroll/pinch to zoom. WebGL-disabled devices retain the numeric game result and show a support message.
- **Sign in**: save character versions and preferences. **New scene** can upload an image to your server library. See [FIREBASE_SETUP.md](FIREBASE_SETUP.md) for the required Firebase project, rules and environment values. This repository does not contain a connected Firebase project.

The online launcher and static deployments use PeerJS/WebRTC and the public PeerServer for signaling. The Keeper's tab must remain open; there is no persistent multiplayer game server or automatic host migration. Up to six connected players. Network restrictions may require your own TURN infrastructure. A dropped player can reconnect with the same invitation and browser-session identity while the host remains open. Imported sheets are validated by the Keeper's client; the application does not independently verify a player's claimed character stats against an external game account.

Changes are on `fix/vtt-session-integrity-and-orbital-ui`. See [RELEASE_ORBITAL.md](RELEASE_ORBITAL.md) for history and [PRUEBAS_LOCALES.md](PRUEBAS_LOCALES.md) for the Windows launchers and LAN setup.

## Preparing a new release

Update the application version in `package.json` and both root version fields in `package-lock.json`. Prepend an entry in `src/releaseHistory.js`, preserving previous entries, and run `npm run release:notes`. `npm run release:check` verifies that package versions, the current release entry and the generated `CHANGELOG.md` agree; `npm run build` runs this check automatically. Use `VeilFarers_VTT_v<VERSION>.zip` for the release archive and `VeilFarers_VTT_Changelog_v<VERSION>.md` for downloaded notes. Keep launcher filenames stable inside the versioned package. Update this README's release line and heading for each release.
