# VeilFarers VTT · v2.43.3

A local-first virtual tabletop for Veilfarers with scene travel, a player roster, shared drones, character creation and level-up, character JSON import, optional Firebase accounts and persistent rooms, and 3D Hope & Fear dice.

Current release: **v2.43.3**. Download package: **VeilFarers_VTT_v2.43.3.zip**. Open **AYUDA** in the top menu for the installed version, quick guide and changelog. The application version is independent of Corebook 12.06. [CHANGELOG.md](CHANGELOG.md) records numbered releases; [RELEASE_ORBITAL.md](RELEASE_ORBITAL.md) retains the original technical history.

## Run locally

On Windows, extract the ZIP and run **INICIAR_VTT_RED_LOCAL.bat** on the Keeper’s PC. Other devices on the same Wi-Fi or Ethernet network open the printed address, for example `http://192.168.1.42:5173/`. Create a game in **Session** and share its invitation. Players select **PLAYER → Join game** and paste the invitation. The Keeper sees **Crew · 1** after the first player joins. Assign a token in the roster. Dropping it on either map updates its position for the other participants. The LAN launcher sends game data through the same VTT server on port 5173. It works without public signaling after dependencies are installed.

**INICIAR_VTT_LOCAL.bat** opens the menu for LAN, single-PC offline play, tests and the effects lab. **INICIAR_VTT_ONLINE.bat** uses persistent Firebase rooms when Firebase is configured; without Firebase it retains the legacy PeerJS connection mode. The launchers require Node.js 22.12+ or 24 LTS and install locked dependencies on first use.

On macOS/Linux, run `npm ci`, then `VITE_SESSION_TRANSPORT=lan VITE_LOCAL_ONLY=0 npm run dev -- --host 0.0.0.0 --port 5173 --strictPort` for LAN play. Run `node scripts/lan-info.mjs` to display client URLs. For local checks use `npm test` and `npm run build`.

## What is new in V2 (v2.0–v2.8)

Development happens on the `V2` branch. [HANDOVER_V2.md](HANDOVER_V2.md) records every decision and the technical notes per version; [CHANGELOG.md](CHANGELOG.md) lists each release.

- **Lobby.** Violet command centre with a **Básico / Avanzado** switch. **Mis personajes** is the private character library of your account (create, import a sheet JSON, download, delete). A guest plays locally and has no library. Room lookup errors are shown with a retry instead of an empty list.
- **Account.** Sign in with email and password or with Google, or enter as a local guest. Netlify Identity sign-in was removed in v2.8.1. Per account: joined rooms, characters, scenes, preferences and personal notes per room. Per Keeper room: arcs, maps and configuration. The account window (signed in) has three tabs: **Partidas y notas** (your rooms, with your private notes for each; open another room from there), **Personajes** and **Preferencias**; **Mis notas** in SESSIONS opens the notes of the room you are in. Each room also shows the character you play there and when you last played (recorded by the table in `users/{uid}/games`; publish the v2.13.0 rules).
- **Character creator.** **Roster → + PERSONAJE** (also in the lobby) builds a character step by step from the Corebook 12.06 rules: ancestry, community, path, class and subclass, traits, experiences, affiliation, powers or Resolve Moves, and starting equipment. The result becomes a token, replaces an existing token, goes to your account or is downloaded. It is independent of the external Character Creator project; the only contact is importing a sheet JSON.
- **Sheet.** Tabs **Ficha / Rasgos / Vínculos / Armas y equipo / JSON**, with **Básica** and **Completa** views. **Subir de nivel** spends the two Advancement Slots and applies Tier Achievements; a Sleeping character can **Despertar** (Awakening) and re-spend refunded slots.
- **Attack.** **Dice → Damage → ATACAR AL OBJETIVO** runs the whole procedure: range check, attack roll against Evasion, and damage only on a hit. Players roll Hope and Fear with the weapon Trait; Keeper adversaries roll 1d20 + Attack and a natural 20 is a critical. Applying the damage is a separate step and the defender chooses how many Armor Slots to spend.
- **Range.** Melee is an adjacent square or 1 m, Very Close up to 5 m, Close up to 10 m, Far up to 25 m, Extreme beyond. A melee weapon, or no weapon at all, only attacks at Melee. A ranged weapon beyond its band attacks with Disadvantage. A wall or closed door in the line of fire is warned about but does not stop the attack. The lock line and the ruler show both metres and the band.
- **Advantage and Disadvantage.** The d6 is thrown on the table and added or subtracted in full; the sum is written out, for example `Hope [2] + Fear [4] + 2 − d6 [6] (Desventaja) = 2`.
- **Damage.** Damage dice are thrown in 3D and their faces are the damage. Proficiency multiplies one listed die (`2d8+2` at Proficiency 3 is `4d8+2`); a player Critical doubles the dice, a Keeper Critical maximises them. Honed Edge is level − 1 for Sleeping characters. Damage types apply Penetration (Energy 2, Void and Neural 4) unless the target has Reflective armor or a Ward; Crushing and Bleed are supported.
- **Card hand.** In the player stance, selecting your character splits the bottom bar in two: its stats on the left and its hand of 3D cards on the right. The hand is the Loadout: Powers for the Awakened, Resolve Moves for the Sleeping, the Uncanny Archive for a Sleeping Mystic, plus the class feature, Ancestry and Background cards. Cards carry the flag and name band of their Domain or Class. Click a card to read it; drag it onto the map to play it. Playing pays the printed cost, announces the card, marks the spot and prepares the roll the card asks for. Ancestry cards are the Gifts that are used, one card each; passive Gifts stay on the sheet. When a player uses a card the Keeper sees it small in the bottom-right corner of the map and can click it to read who used it and what it does; the chat line says the same. The **deck** after the cards opens a drawer (Loadout above, Vault below) that brings other known Powers into the Loadout with a Recall at the Corebook's price (free on a Long Rest, Recall Cost in Stress on a Short Rest, plus 1 Hope and your Action in a scene).
- **Keeper hand.** In the Keeper view the bottom of the map holds the four Fear moves of the Corebook and, with an adversary selected, its printed abilities as cards (type and Fear cost read from the book text). Playing one spends the Fear and tells the table, unless secret rolls are on. Sleeping characters also hold **Bear Down** (any number of Resolve dice; a missed attack that now reaches the Evasion hits) and the Common Efforts, usable with Burnout at 0 Effort.
- **Drones.** **Roster → + DRONE** builds a drone the way Corebook chapter 14 does: a Grade (Common, Military, Experimental) plus Modules from a searchable catalog of 102 (Corebook and Rust & Steel), or one of the eight sample builds. Slots, illegal modifications and the lethal-weapon lock of Common drones are checked. Each drone has an operator, a signal state, a link mode and a Lost protocol; it attacks with its operator's roll (Disadvantage on Unstable signal, no command on Lost), loses 2 Evasion while Lost, and its weapons never scale with Proficiency. **Ficha → Dron · módulos y señal** reopens the console and rolls the Drone Complication. A drone is paired to one player unless it carries **Neural Network Control**: then the Keeper registers several players and they pass control by turns (free on Stable signal, 1 Stress for the receiver on Unstable, impossible on Lost).
- **Lighter first load (v2.14.1).** The 3D dice engine warms up once the page has loaded and the browser is idle; card rules data loads only when a hand is shown; token portraits and sample maps were recompressed (same paths).
- **First-use guide.** At the table, a short checklist for your role (player or Keeper) sits at the top right of the map. Steps tick themselves when you really do them (move your token, roll, play a card, spend Fear…); **Show me** highlights the control a step talks about. It can be minimised, skipped step by step, closed, and reopened or restarted from **Help → First steps** (*See the first steps again* / *Start from scratch*).
- **Technology Access (v2.15.0).** Gear is filtered first by what the character can use (class, level, Technology Access; the box is ticked by default). Anything used outside that training rolls with Disadvantage (weapon, worn armor and augmentations, the drone). Failure with Fear on an attack suggests a consequence from the weapon. The deck drawer shows every Power, with *Only those I can access* ticked by default; Powers within reach can be added to the Vault.
- **(V3) Player bar and dice icon.** In player stance an action bar sits above the character: ROLL (the six Traits, one touch) and ATTACK (one button per weapon, then the target on the map), with the attack result and *Apply damage*. The dice are a translucent icon in the top corner of the map; for players it only gives dice.
- **(V3) Weapon tags, damage riders and Resolve.** Weapons carry canonical tags the rules read (no word search); Combat Surge, The Held Line, the Nirvana first strike and Breaking Point add to an attack's damage; Sleeping characters use Bear Down and Prepare from the Sheet.
- **(V3) Token light follows the token.** While a token is dragged into place, and while it slides there, its own light moves with it; vision and fog keep the confirmed position.
- **(V3) Vision slides with the token.** The lit area in the Fog of War moves with a sliding token instead of jumping ahead of it.
- **(V3) Rests and enemy armor.** The Keeper's crescent moon (Short Rest) and rising sun (Long Rest), top-left of the map, pause the table; each character chooses two different rest moves (Corebook ch. 9), the panel shows who is still choosing, and the last choice applies the rest. Armor Piercing, Disintegrating and Shredding cut an enemy's maximum Armor Slots at once. Roll result cards are 40% transparent and leave sooner.
- **(V3) Every roll in 3D; the attack ends with the damage.** Rest dice, Bear Down, damage riders, rolled card durations and Keeper card dice are thrown as 3D dice and the table applies the faces shown. Applying damage closes the attack and deselects the tokens.
- **(V3) Lights, Weather and arrow keys.** Scene darkness (Foundry-like) is always drawn and lights really light it, with walls; by day tokens see their whole line of sight, at night their own vision plus lit areas, and only what is seen is explored. Light animations work. The Water tool became Weather: Day / Dusk / Night transitions over 10 s, a darkness slider, rain and fog, and water or lava zones drawn as box, polygon or freehand. Arrow keys move the selected token one square.
- **(V3) Fewer Firebase requests; light switches.** Room messages carry only the changed items and fields, saves are grouped and rewrite only the changed piece, and the presence heartbeat is slower: about half the Firestore operations per action. Lights can be switched off, lit lights dissipate the fog by their intensity, and switches (usable or locked, visible or secret) turn groups of lights on and off. Connected players can open doors again.
- **(V3) Live play on Realtime Database.** Room messages and player presence travel through Realtime Database (billed by data, not by operation); Firestore keeps accounts, rooms and saves. Without it, rooms fall back to Firestore. Setup: FIREBASE_SETUP.md.
- **(V3) Fog sync, Keeper damage window, movable panels.** Explored fog reaches every player; damage to NPCs and adversaries opens a Keeper window (shields, apply or cancel); a Normal button sits next to Advantage/Disadvantage; the card hand and the character bar can be dragged; cards show name and cost at the top.
- **(V3) Corebook 12.06 texts.** Powers, Path features, Resolve Moves, Ancestry Gifts and Communities match the Corebook; Path to Nirvana and the Disciplined State use the Integrity Die. The deck also shows Ancestry, Community and class cards (Awakened / Sleeping, by class).
- **(V3) Effect clocks.** Cards with a duration (Path to Nirvana, Rapid Regeneration…) put a clock beside the token; each Spotlight marks a segment, a touch marks one by hand, and the full sheet edits it.
- **(V3) 3 + 5 + rest.** In the player's view, the header, map tools and character bar show three controls and a «⋯» menu (five more, then «More…» with the rest).
- **(V3) Rolling in two touches.** Tap a Trait to select it, tap it again to roll, or choose Advantage/Disadvantage. With a Trait selected, the character’s Experiences appear: Awakened ones need Hope and mark the Hope they will spend; Sleeping ones are free.
- **(V3) Player sheet in the right panel.** For players the right panel has five tabs: Sheet, Ship, Dossiers, Log and Chat. ROLL, Experiences and ATTACK live in the Sheet tab instead of floating over the map. The tab also shows Evasion, Thresholds, Shields, armor, HP, Stress, Hope or Effort/Resolve and pending effects; roll results are small cards at the bottom centre. Firearms with a maximum range of Close have no Disadvantage at Close or in Melee. Experiences are always listed on the Sheet; an attack marks the target on the first tap and attacks on the second.
- **Phones and tablets.** The table is designed for a computer or tablet. On a phone a one-time notice says so; the guide starts minimised and the layers panel and map clocks are hidden. On a tablet the layers panel moves to the top right of the map.
- **Language.** The interface shows in one language, Spanish by default, with an **ES / EN** switch in the status bar and in the lobby corner; the choice is remembered. Corebook rule terms (Hope, Fear, Stress, Evasion…) stay in English in both, and chat, names and book text are never translated. The help and the notices (toasts and error messages) follow the same switch; release notes keep the language they were written in. The **⌂** button (or the VEILFARERS badge) goes back to the home screen without closing the table.
- **Roll results.** One golden card per roll on the right, stacked in arrival order so every player's roll is visible, plus the chat line. Secret Keeper rolls stay with the Keeper.
- **Chat.** Press **Enter** on the map to write to the table chat.
- **Light and fog of war.** Vision and lights are round, fade towards the end of their range and have feathered edges; walls still block them.

## Persistent rooms and map editing (since v1.4.0)

- Sign in with a Firebase Google/email account and open **SESIONES**. Create a room from a copy of the current local campaign, or accept a `VF-…` invitation once. Your rooms remain in the account list; reopening restores the campaign.
- The Keeper assigns tokens, removes access or readmits members. Rotating the invitation only changes future entries. The current room name and connection state stay in the top menu.
- **Dibujar [B]** opens the custom color palette and three widths. **Borrar [D]** removes only freehand strokes. Keeper undo includes drawings. Players can draw and erase their own strokes while connected.
- Select a map element and press **Ctrl+C / Ctrl+V** (Cmd on macOS). Copies are offset one grid cell per paste. Keeper copies tokens, walls, lights, water, anomalies, drawings and area templates; players copy their own drawings. Token copies have no player assignment. Text field shortcuts retain their usual behavior.

## Encounters in v1.2.0

- **SCENES → Definir entorno / activar con Fear**: choose the micro stat block and one Passive or Action macro feature (Keeper 12.06, chapters 9–10). Tier scaling and DC are shown from the book. Save before activating; Fear costs are printed costs, and reactions require the stated trigger. Roll and resolve consequences at the table. Visuals are optional and separate from weather.
- **ROSTER → Biblioteca de adversarios → Colocar como boss**, or an enemy **Ficha → Boss · estados**: configure 2–8 phases or load one of 17 Keeper profiles. Unprinted values visibly inherit the base adversary. Review them before play. Transitions are Keeper-controlled; +2 Fear, or +3 for the final phase, capped at 12. Objective/clock mechanics and special abilities follow their source text, not automatic damage logic.
- **DICE → Damage → Impacto del arma**: weapon-derived or explicit presentation. Only applied damage triggers an impact, sized from actual HP lost. Armor expenditure produces shield feedback; direct bypass does not. `/fx-lab.html` demonstrates ballistics, plasma, fire, cryo, explosions and clipped fire areas.
- In **SCENES**, choose another arc or **Sin arco** for any scene. Wait for **SAVED** before closing or reloading. Arc membership is now part of campaign persistence and export.

## Play

- **Water → Polígono**: click each vertex, then click the first vertex, double-click, press Enter or select **Cerrar polígono**. Backspace removes the last point; Escape, right-click or **Cancelar** discards the draft. Switching tools, shapes, scenes, roles or layers also discards unfinished water. The actual polygon is saved and shared, including coordinates at zero; **Caja** remains drag-to-draw. Water must be visible and unlocked. Existing zones previously saved as default rectangles have no original vertices to recover and must be redrawn.
- **CHAT**: select **Mesa · todos** for public messages or a private Keeper–player conversation. The Keeper can also use **Session → Player roster → Susurrar**. Players can whisper to the Keeper; player-to-player whispers are not included. Enter sends, Shift+Enter inserts a line, and each channel keeps a separate draft. Unread counts identify conversations with new messages. A disconnected recipient disables sending without changing the destination; a failed send retains the draft for retry.
- Chat keeps the last **500 messages across the session**, with up to 2000 characters each. The Keeper's saved session and JSON export contain public messages and whispers. Guests only receive public messages and their own whispers, including reconnect snapshots; these do not overwrite the guest's local campaign. In persistent rooms the account restores its own available history. Legacy/LAN sessions use their browser-session identity while the host remains open. A new browser identity cannot retrieve another player's private thread. There are no read receipts or offline delivery queue. Local Keeper messages are saved to the table and become visible when players join.
- **Token → ESTADOS** or **Ficha → Condiciones**: toggle the 18 standard conditions from Corebook 12.06, Chapter 10, with the original rules available in the panel. Add custom markers for scene-specific effects. Icons appear beside visible tokens and labels appear in the quickbar. Conditions are shared, saved and undoable; their effects and durations are resolved manually. The Hidden condition does not make a token private. The Keeper and assigned players can edit; other players can consult.
- **Token → EQUIPO** or **Ficha → Armas y equipo**: everything is done in the tab itself. Search the catalog by name or category and add an entry with one click, change quantities with − and +, edit or remove each weapon and item on its own row, or create your own with **+ Arma propia** / **+ Objeto propio**. Changes are saved at once. **Atacar** takes a weapon to the dice panel and retains its selected target. Imported final damage is not expanded a second time; base damage adds Proficiency and Honed Edge once. Expressions such as `1d8+1 Phys + 1d4 Shock` are supported. Alternative attacks, keep-highest procedures, resistances and special features need manual resolution. Inventory edits are stored in sessions and native VTT actor exports; **Exportar al creador** retains the original creator equipment. Reimporting a system sheet preserves an existing VTT inventory override.
- **Dice → Tirada secreta · solo Keeper**: hide a check, Bear Down or damage roll from player logs and network messages. The Keeper can roll without selecting a token. Private results remain in the Keeper's saved session; switching to Player hides them. Resource changes on visible characters still synchronize normally. Session exports contain Keeper information and are intended for the Keeper.
- **Roster → Biblioteca de adversarios**: search by name, ability or type, then filter by book and tier. The catalog reads the supplied 12.06 texts: Alien Species (Threats and Adversaries), Keeper’s Companion (Galactic Bestiary, Section A), and Rust & Steel (Broker Profiles). It contains 57 profiles, 42 directly deployable. Each deployed copy has independent resources and appears hidden by default at the center of the current view. Full printed descriptions and abilities remain in **Ficha → Notas y habilidades**. The other 15 profiles stay available for reference because they require special encounter procedures or lack complete numeric thresholds. Unprinted Stress/Armor tracks have zero slots; printed abilities open their table procedure from the Keeper hand. See [Poderes en mesa](docs/poderes-en-mesa.md) for the catalogue and its adjudication rules.
- **Legacy/LAN Session** → Host game: name the current campaign and copy its invitation. Players paste the complete code or link and enter their call sign. An account is optional. The top menu always shows connection state, campaign name and invitation.
- **Session** → Player roster: the Keeper assigns any non-drone token to a player. Reassignment releases that player's previous token. Players can import their own character or use a cloud character; replacement keeps their existing token and assignment.
- **My tokens** opens the character and shared drones you control in the current scene. Select one to center the map, move it, aim its facing handle, make a check or edit its current resources in **Ficha**. The Keeper manages assignments and resource limits.
- **Anomaly color** opens a palette for lightning and laser effects. Drag in the color field, adjust hue, choose a swatch or enter a hex value. The effect previews the selected color immediately.
- **Roster** → + Actor → Drone: create a drone. In its **Ficha → Player controls**, select multiple controllers. Drone controls are also available in Session. Non-drone tokens allow one controller; a player may control one non-drone plus several drones.
- **Scenes**: switching or creating a scene moves player characters, assigned NPCs and controlled drones. Encounter enemies stay behind. Returning restores per-scene positions, clamped to map bounds. Keeper-owned legacy enemies are not party members.
- **Dice**: with **3D** on, the dice are thrown over the map (`@3d-dice/dice-box`) and the faces they show are the result; choose the Plain, Tech or Crystal finish in the dice panel. With 3D off, or on a device without WebGL, the same roll is resolved as numbers. Each result appears once as a golden card on the right and as a line in the chat.
- **Sign in**: save character versions and preferences. **New scene** can upload an image to your server library. See [FIREBASE_SETUP.md](FIREBASE_SETUP.md) for the required Firebase project, rules and environment values. This repository does not contain a connected Firebase project.

With Firebase configured, online rooms use authenticated Firestore channels and durable campaign checkpoints. Membership is stored by UID and survives refreshes, new devices, invitation rotation and Keeper disconnects. The Keeper remains the authority for game actions; players wait inside the room while the owner is offline. There is no automatic transfer of ownership. Sudden disconnects expire after a 20-second server lease. Uploaded image URLs are reused; unchanged state sections and stored image fragments are not retransmitted on each token move. A room campaign has a 60 MiB serialized-text limit; use hosted image URLs for large maps. Firestore operations consume your project's reads/writes/storage. See [FIREBASE_SETUP.md](FIREBASE_SETUP.md) for deployment and isolation from the public portal.

LAN and the unconfigured legacy PeerJS mode remain available, with their previous temporary-session behavior. Legacy invitation codes cannot be converted into account memberships: open the saved local campaign, create a persistent room and invite each player once. Imported character stats still require Keeper review.

Current work is on the `V2` branch. See [RELEASE_ORBITAL.md](RELEASE_ORBITAL.md) and [RELEASE_v1.4.0.md](RELEASE_v1.4.0.md) for earlier history and [PRUEBAS_LOCALES.md](PRUEBAS_LOCALES.md) for the Windows launchers and LAN setup.

## Preparing a new release

Update the application version in `package.json` and both root version fields in `package-lock.json`. Prepend an entry in `src/releaseHistory.js`, preserving previous entries, and run `npm run release:notes`. `npm run release:check` verifies that package versions, the current release entry and the generated `CHANGELOG.md` agree; `npm run build` runs this check automatically. Use `VeilFarers_VTT_v<VERSION>.zip` for the release archive and `VeilFarers_VTT_Changelog_v<VERSION>.md` for downloaded notes. Keep launcher filenames stable inside the versioned package. `npm run release:notes` also writes the current version into this README's heading and release line and into the version paragraph of `PRUEBAS_LOCALES.md`, and `release:check` fails if they are behind. When a release changes how something works, update the matching section of `README.md`, `PRUEBAS_LOCALES.md` and `FIREBASE_SETUP.md` in the same commit.
